1. Executive Summary & Core Topology

The WhatsApp Gateway serves as an autonomous, self-hosted communication bridge that provides enterprise microservices, CRMs, and automated AI agents with reliable, ban-safe programmatic access to WhatsApp.

Unlike conventional wrapper libraries that crash on redeployments or get numbers banned within minutes due to uncontrolled bursts, this platform implements a hardened, multi-tier architecture:

  • Transactional Outbox: Decouples synchronous HTTP requests from asynchronous WhatsApp socket transmissions with 100% ACID consistency.
  • Anti-Ban Engine: Enforces mathematical rate limits (4 msgs/min strict cap, 5s inter-message hardware gap, 10s same-recipient cooldown, 6 new contacts/hr velocity cap, and 45–90s burst pauses).
  • RAG AI Support Bot: Retrieves semantic documentation chunks from PostgreSQL using vector cosine similarity, passing context to Google Gemini 1.5 Flash to automatically answer customer queries.

Schema Entity Overview

  • sessions: Tracks multi-device pairing state (starting, qr, connected, logged_out), phone numbers, and last activity timestamps.
  • auth_states: Stores cryptographic Signal keys, pre-keys, and app-state sync credentials directly in PostgreSQL JSONB, enabling instant container redeployment without physical QR re-scanning.
  • messages: Complete audit log of all inbound and outbound messages, statuses (queued, sent, delivered, read, failed), and idempotency keys.
  • outbox_jobs: The execution queue containing message payloads, retry counters, locking metadata (lockedAt, lockedBy), and cooldown timestamps (nextRetryAt).
  • knowledge_documents & knowledge_chunks: The RAG repository storing document metadata alongside 768-dimensional vector embeddings.
  • webhooks & webhook_deliveries: Subscribed HTTP callback endpoints and immutable dispatch audit logs.

The Core Dequeue Query

UPDATE "outbox_jobs"
SET 
  status = 'processing',
  "lockedAt" = :now,
  "lockedBy" = :workerId
WHERE id = (
  SELECT id FROM "outbox_jobs"
  WHERE status = 'queued'
    AND "sessionId" = :sessionId
    AND "nextRetryAt" <= :now
  ORDER BY id ASC
  FOR UPDATE SKIP LOCKED
  LIMIT 1
)
RETURNING *;

4. WhatsApp Driver Layer: Baileys vs. Alternatives

Why Baileys Was Chosen

  • Zero Per-Message Fees: Unlike Meta's Cloud API (which charges $0.03–$0.08 per 24-hour conversation window and requires corporate Meta Business verification), Baileys connects via native WhatsApp multi-device WebSockets with zero API charges.
  • Lightweight Resource Consumption: Unlike Puppeteer or Selenium (which spawn headless Chromium instances consuming 800MB–1.5GB of RAM per session), Baileys operates purely in JavaScript memory (<40MB RAM per session) using WhatsApp's binary Protobuf protocol.
  • PostgreSQL Signal Key Adapter: Stores all identity keys, signed keys, and pre-keys in PostgreSQL rather than local disk files, preventing file-lock corruption across clustered Docker containers.

5. The Multi-Tier Anti-Ban Engine & Behavioral Pacing

WhatsApp uses automated behavioral heuristics to detect automated accounts. The gateway implements an enterprise Anti-Ban Engine (src/services/antiBan.service.js) enforcing 6 strict mathematical barriers:

Rule 1: Rolling 60-Second Window (Max 4 msgs/min in Strict Mode): An array of timestamps in the last 60 seconds is inspected. The 5th message is deferred until the oldest message falls out of the window.
Rule 2: Hardware Minimum Gap (5.0s): Enforces a mandatory cooldown of 5,000ms between any two consecutive dispatches, preventing burst spikes.
Rule 3: Same-Recipient Cooldown (10.0s): Prevents spamming the same recipient. Messages to the same contact are paced at least 10 seconds apart.
Rule 4: Cold Contact Velocity Limiter (Max 6 New Contacts / Hour): Prevents accounts from mass-messaging unknown contacts. The 7th new contact in an hour is deferred to the next hour.
Rule 5: Natural Burst Pauses ("Coffee Break"): After 10 continuous messages, injects a natural human pause of 45 to 90 seconds.
Rule 6: Daily Warmup Schedule (Day 1: 25 msgs/day): New numbers start at 25 msgs/day, increasing by 20% daily at midnight up to 300 msgs/day.

7. Networking, Webhooks & Communications: Why Not Socket.io?

  • WhatsApp Protocol Incompatibility: WhatsApp Web communicates via binary WebSockets using the Noise Protocol. Socket.io cannot talk to WhatsApp's native socket protocol.
  • Webhooks Are the Industry Standard for B2B: External microservices, CRMs, and serverless functions (AWS Lambda, Cloud Run) cannot maintain persistent Socket.io connections. They require standard signed HTTP POST webhooks (POST /webhook).
  • HMAC-SHA256 Signing: All webhook deliveries include an X-Signature header computed as: sha256 = HMAC_SHA256(rawBody, webhookSecret), ensuring payloads cannot be forged or tampered with in transit.

Step-by-Step Mechanism 1: Server Bootup & Auto-Restoration

[Gateway Boot] ──► [loadConfig / .env]
                       │
                       ▼ 1. Test PostgreSQL Connection & Run Migrations (001 - 008)
                       ▼ 2. Re-queue Stuck Jobs: UPDATE outbox_jobs SET status='queued' WHERE status='processing'
                       ▼ 3. Query Active Sessions: SELECT * FROM sessions WHERE status='connected'
                       ▼ 4. Staggered Socket Spin-up (1.5s delay between sessions)
                       ▼ 5. Spawn independent senderWorker loop per session
                       ▼ 6. Start Watchdog (30s recurring health heartbeat)
                       ▼ 7. RAG Auto-Seed: If knowledge_documents empty, chunk & embed documentation
                       ▼ 8. Express 5 begins listening on PORT with static /uploads mounted
  1. Configuration Loading: Loads environment variables, validates database credentials, anti-ban profile (strict/moderate/relaxed), and AI settings.
  2. Database Migration Check: Verifies all 8 migrations (sessions, auth_states, messages, outbox_jobs, webhooks, webhook_deliveries, api_keys, knowledge_base) are applied.
  3. Crash Recovery & Lock Reclamation: Any jobs left in status: 'processing' from a previous server crash are immediately reset to 'queued' with lockedBy = null.
  4. Session Reconnection: Queries all previously connected sessions from sessions table and loads cryptographic Signal keys from auth_states.
  5. Staggered Socket Startup: Connects Baileys instances staggered 1.5 seconds apart to avoid simultaneous connection bursts to WhatsApp servers.
  6. Worker Spawning: Launches a dedicated senderWorker instance for each active WhatsApp session.
  7. Watchdog Activation: Starts a 30-second recurring watchdog (src/workers/watchdog.js) monitoring socket readyState.
  8. RAG Auto-Seeding: Automatically inspects knowledge_documents; if empty, ingests the system documentation, generates 768-D vectors via Google text-embedding-004, and indexes them in PostgreSQL.

Step-by-Step Mechanism 3: Outbound Message Sending with Anti-Ban Pacing

[Client Application] ──POST /messages/text──► [Gateway API]
                                                    │

                                                    ▼ 2. Validate JID & Payload (Zod)

                                                         - Insert outbox_jobs (status='queued')

[senderWorker] ──outboxService.dequeue()──► [FOR UPDATE SKIP LOCKED]
       │

       │

       │   outboxService.reschedule(job.id, cooldownMs)

  1. Client Request: External service sends POST /api/v1/sessions/:id/messages/text.
  2. API Key Verification: Token hash verified against api_keys for send permission.
  3. Atomic Outbox Commit: Single SQL transaction inserts into messages and outbox_jobs. Client instantly receives HTTP 202 Accepted.
  4. Single-Stream Dequeue: senderWorker executes SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1.
  5. Anti-Ban Gatekeeper: Checks 6 hard rules: 4 msgs/min window, 5s hardware gap, 10s same-recipient gap, 6 cold contacts/hr, 45-90s burst rest, daily warmup cap.
  6. Reschedule on Limit: If restricted, the job is unlocked and rescheduled in PostgreSQL for NOW() + waitMs. Worker memory remains free.
  7. Human Presence Emulation: Emits available and composing (phone shows "typing..."), waiting 35-75ms per character.
  8. Socket Dispatch & Jitter: Message transmitted via Baileys WebSocket; status marked 'sent'; worker sleeps 4-9s random jitter before next job.

  2. Safety Guardrails: Verifies fromMe === false, confirms no human agent replied in the last 5 minutes, and checks sliding rate limit (≤ 5 replies/min).
  3. Dense Vector Embedding: Generates a 768-dimensional normalized float embedding via Google's text-embedding-004.
  4. PostgreSQL Cosine Similarity Search: Executes cosine_similarity(embedding, queryVec) to find the top 4 most relevant documentation snippets.
  5. Multi-Turn Context: Retrieves recent 6 messages from messages table to provide conversational continuity.
  6. AI Synthesis: Google Gemini 1.5 Flash synthesizes an accurate, grounded, helpful answer via LangChain JS.
  7. Outbox Pacing: The reply is enqueued into outbox_jobs, paced through human typing emulation, and sent back to the customer's WhatsApp chat.
